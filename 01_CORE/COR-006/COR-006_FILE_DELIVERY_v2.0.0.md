# 1. 목적과 비목적

## 1.1 목적

파일 전달의 목표는 수신자가 올바른 산출물을 식별하고 안전하게 내려받아 열고 검증하며 의도된 후속 작업에 사용할 수 있게 하는 것이다.

## 1.2 비목적

이 문서는 콘텐츠 작성·조사·출처 원칙, 채널별 발행 전략, 버전 번호·승인 상태 전환, 저장소 운영과 자동화 도구별 구현 절차를 정의하지 않는다.

## 1.3 결과 기준

좋은 전달은 무엇을 왜 받는지, 어느 파일이 기준본인지, 어떻게 열고 검증하는지, 제한과 누락이 무엇인지 명확하며 재전달 없이 사용할 수 있다.

# 2. 적용 범위와 책임

## 2.1 적용 대상

문서, PDF, 스프레드시트, 프레젠테이션, 이미지, 코드, 데이터, 웹 패키지, 압축 파일과 복합 산출물에 적용한다.

## 2.2 제작자 책임

제작자는 요구 형식과 대상 환경을 확인하고 파일을 생성하며 이름·구조·내용·무결성·보안을 검증해야 한다.

## 2.3 전달자 책임

전달자는 올바른 최종본, 접근 가능한 위치, 필요한 설명과 제한을 제공하고 전송 실패나 권한 문제를 확인해야 한다.

## 2.4 수신자 역할

수신자 확인이 필요한 작업에서는 파일 접근, 열림, 무결성과 누락 여부를 확인하고 문제를 보고한다.

# 3. 상위 규칙과 인접 문서

## 3.1 COR-001 상속

사용자 요청 우선, 기존 파일 보존, 범위 통제, 실패 보고, 외부 상태 변경과 승인 원칙은 COR-001을 상속한다.

## 3.2 COR-005 연결

완료 전 내용·형식·기능·렌더링과 패키지 QA 및 PASS 판정은 COR-005를 따른다.

## 3.3 COR-007 경계

버전 번호, 승인 상태, 기준본 전환과 LOCKED 절차는 COR-007에서 정의한다.

## 3.4 Publishing 경계

채널 게시, 공개 일정, SEO와 배포 전략은 후속 Publishing System에서 정의한다.

# 4. 전달 요구사항

## 4.1 수신자와 목적

전달 전 수신자, 사용 목적, 편집 필요 여부, 대상 환경과 후속 작업을 확인한다.

## 4.2 필수 파일

요청된 본문 파일, 편집본·고정본, 원본 자산, 데이터, 설명서와 검수 자료 중 필요한 항목을 명시한다.

## 4.3 제약

파일 크기, 허용 형식, 채널 제한, 보안 등급, 마감, 접근 권한과 보존 기간을 확인한다.

# 5. 파일 형식과 변형

## 5.1 형식 선택

형식은 사용자 요구와 사용 목적을 우선하며 편집성, 고정 레이아웃, 기계 처리, 호환성과 파일 크기를 함께 고려한다.

## 5.2 편집본과 고정본

후속 편집이 필요하면 원본 구조를 보존한 편집 가능 파일을 제공하고, 모양 보존이 필요하면 PDF 등 고정본을 함께 제공할 수 있다.

## 5.3 변환

형식 변환 후에는 내용, 글꼴, 수식, 링크, 이미지, 페이지와 상호작용 손실을 다시 검수한다.

# 6. 파일명·경로·구조

## 6.1 파일명

파일명은 문서 ID 또는 프로젝트, 제목, 버전과 필요한 상태를 일관된 순서로 포함하며 모호한 `final`, `new`, `latest`만으로 구분하지 않는다.

## 6.2 안전한 문자

대상 운영체제와 채널에서 금지되거나 오해될 수 있는 문자, 예약어, 끝 공백과 과도한 경로 길이를 피한다.

## 6.3 폴더 구조

복합 패키지는 목적별 폴더와 상대 경로를 사용하며 내부 참조가 패키지 이동 후에도 유지되게 한다.

# 7. 생성과 무결성

## 7.1 원본 보존

기존 사용자 파일은 덮어쓰지 않고, 명시적으로 승인된 동일 파일 수정 외에는 새 출력 경로를 사용한다.

## 7.2 생성 검증

파일이 존재하고 0바이트가 아니며 예상 형식으로 열리고 필요한 내용과 구조를 포함하는지 확인한다.

## 7.3 무결성

중요하거나 복합적인 전달은 파일 크기, 개수와 SHA-256 등 검증값을 기록해 전송 전후 동일성을 확인할 수 있게 한다.

# 8. 패키지와 의존성

## 8.1 매니페스트

여러 파일을 전달할 때 파일 목록, 역할, 기준본과 필수·선택 상태를 설명하는 매니페스트를 제공한다.

## 8.2 의존성

글꼴, 데이터, 라이브러리, 템플릿, 링크, 매크로와 실행 환경 등 사용에 필요한 의존성을 명시한다.

## 8.3 압축

파일 수나 채널 제약 때문에 압축할 때는 최상위 폴더 하나, 안정적인 상대 경로와 검증 가능한 압축 형식을 사용한다.

# 9. 보안·개인정보·권한

## 9.1 최소 공개

요청 범위에 필요한 파일과 정보만 전달하며 임시 파일, 비밀값, 개인 경로, 로그와 숨은 메타데이터를 포함하지 않는다.

## 9.2 민감정보 검사

개인정보, 인증정보, API 키, 내부 URL, 댓글, 추적 변경과 문서 속성을 전달 전 검사한다.

## 9.3 권한

링크 또는 공유 위치는 의도한 수신자만 필요한 기간과 권한 수준으로 접근할 수 있게 설정한다.

## 9.4 보호 전달

암호화나 별도 비밀번호 전달이 필요한 경우 승인된 채널과 조직 정책을 따르며 비밀번호를 같은 공개 경로에 두지 않는다.

# 10. 호환성·접근성·사용성

## 10.1 대상 환경

대상 운영체제, 응용 프로그램, 브라우저, 버전과 장치에서 핵심 파일이 열리고 동작하는지 확인한다.

## 10.2 글꼴과 자산

수신 환경에 없는 글꼴·코덱·플러그인에 의존할 때는 허용되는 범위에서 포함, 대체, 임베드 또는 고정본을 제공한다.

## 10.3 사용 안내

특수한 열기 순서, 설치, 추출, 실행, 매크로 허용 또는 데이터 연결이 필요하면 짧고 실행 가능한 안내를 제공한다.

## 10.4 접근성

파일명, 폴더 구조, 문서 태그, 대체 텍스트와 읽기 순서 등 적용 가능한 접근성 정보를 유지한다.

# 11. 다운로드·전송·수신

## 11.1 접근 가능한 전달

파일은 수신자가 실제로 접근할 수 있는 링크, 첨부, 저장소 또는 승인된 전달 채널로 제공한다.

## 11.2 링크 검증

전달 전 링크 대상, 파일명, 권한, 만료, 다운로드 동작과 최신 파일 연결 여부를 확인한다.

## 11.3 수신 확인

중요한 전달은 수신자가 파일을 내려받아 열었거나 시스템이 성공적으로 수신했음을 확인한다.

## 11.4 전달 메시지

전달 메시지에는 목적, 파일 목록, 기준본, 사용 안내, 검수 상태, 제한과 필요한 다음 행동을 포함한다.

# 12. 실패·복구·재전달

## 12.1 실패 보고

업로드·첨부·권한·다운로드·압축 해제·열기 실패를 숨기지 않고 원인, 영향과 필요한 조치를 보고한다.

## 12.2 안전한 재전달

재전달 시 기존 링크나 파일을 임의 교체하지 않고 새 대상 식별자와 변경 이유를 명확히 한다.

## 12.3 대체 경로

채널 크기 제한, 차단 또는 만료가 있으면 승인된 대체 채널이나 분할 패키지를 사용하고 동일성 검증 방법을 제공한다.

# 13. 기록과 인수인계

## 13.1 전달 기록

전달 대상, 파일 식별자, 해시, 시간, 채널, 수신자, 권한, 만료와 결과를 필요한 수준으로 기록한다.

## 13.2 기준본 표시

편집본, 고정본, 원본 자산과 참고 파일 중 어느 파일이 현재 사용 기준인지 명확히 표시한다.

## 13.3 잔여 제한

미포함 의존성, 호환성, 접근 제한, 만료, 미검증 환경과 알려진 손실을 전달 기록에 포함한다.

# 14. 규칙 카탈로그

## 14.A 전달 요구사항과 대상 (FILE-001 ~ FILE-005)

### FILE-001 - 수신자와 목적 확인
- **Priority:** Critical
- **Statement:** 파일 생성 전에 수신자, 사용 목적, 편집 필요 여부와 후속 작업을 확인해야 한다.
- **Rationale:** 같은 내용도 사용 목적에 따라 필요한 형식과 패키지가 달라진다.
- **Verification:** Delivery Brief의 수신자와 Use Case를 확인한다.
- **Exceptions:** 사용자가 형식과 목적을 완전히 지정한 단일 파일 요청은 요청 원문으로 대체한다.

### FILE-002 - 대상 환경 확인
- **Priority:** Critical
- **Statement:** 파일을 사용할 운영체제, 응용 프로그램, 버전, 브라우저 또는 장치를 필요한 만큼 확인해야 한다.
- **Rationale:** 제작 환경에서 정상인 파일도 수신 환경에서 열리지 않을 수 있다.
- **Verification:** Target Environment와 호환성 검사 결과를 대조한다.
- **Exceptions:** 환경을 알 수 없으면 범용 형식과 알려진 제한을 제공한다.

### FILE-003 - 필수 파일 목록
- **Priority:** Critical
- **Statement:** 전달할 필수 파일, 선택 파일, 원본 자산, 설명과 검수 자료를 사전에 정의해야 한다.
- **Rationale:** 전달 후 누락을 발견하면 재작업과 혼선이 발생한다.
- **Verification:** Delivery Manifest와 요구사항을 비교한다.
- **Exceptions:** 단일 파일 전달은 파일 하나와 목적만 기록할 수 있다.

### FILE-004 - 채널 제약 확인
- **Priority:** High
- **Statement:** 파일 크기, 허용 형식, 링크 만료, 권한, 보안과 보존 기간 등 전달 채널 제약을 확인해야 한다.
- **Rationale:** 채널 제한은 정상 파일의 업로드와 접근을 막을 수 있다.
- **Verification:** Channel Constraints와 실제 패키지 속성을 비교한다.
- **Exceptions:** 로컬 전달은 적용 가능한 파일시스템 제약만 확인한다.

### FILE-005 - 범위 밖 파일 제외
- **Priority:** Critical
- **Statement:** 요청과 사용 목적에 필요하지 않은 사용자 파일, 작업 사본, 로그와 내부 자료를 전달 범위에 포함하지 않는다.
- **Rationale:** 불필요한 파일은 혼선, 정보 노출과 기준본 오선택을 만든다.
- **Verification:** 최종 파일 목록과 승인 범위를 대조한다.
- **Exceptions:** 감사용 이력은 별도 승인된 위치와 상태로 분리한다.

## 14.B 형식과 변형 (FILE-006 ~ FILE-010)

### FILE-006 - 사용자 요구 형식 우선
- **Priority:** Critical
- **Statement:** 명시된 파일 형식과 편집 가능성 요구를 우선 충족해야 한다.
- **Rationale:** 임의 형식 변경은 후속 사용 흐름을 깨뜨린다.
- **Verification:** 요청 형식과 실제 확장자·내부 형식을 확인한다.
- **Exceptions:** 생성 불가능하거나 안전하지 않으면 대체 형식과 이유를 먼저 보고한다.

### FILE-007 - 확장자-내용 일치
- **Priority:** Critical
- **Statement:** 파일 확장자는 실제 내부 형식과 일치해야 한다.
- **Rationale:** 이름만 바꾼 파일은 열기 실패와 보안 경고를 만든다.
- **Verification:** 파일 시그니처 또는 신뢰 가능한 파서로 형식을 확인한다.
- **Exceptions:** 없음.

### FILE-008 - 편집본 구조 보존
- **Priority:** High
- **Statement:** 편집 가능 파일은 텍스트, 수식, 표, 레이어, 시트와 구성요소를 가능한 범위에서 실제 편집 가능한 구조로 유지해야 한다.
- **Rationale:** 이미지로 평면화된 편집본은 수정을 어렵게 한다.
- **Verification:** 대표 요소를 선택·편집하고 구조를 감사한다.
- **Exceptions:** 원본 구조가 없거나 보호가 필요한 요소는 제한을 명시한다.

### FILE-009 - 고정본 제공 조건
- **Priority:** High
- **Statement:** 레이아웃 보존이나 검토가 중요하면 편집본과 구분되는 고정 레이아웃 파일을 제공해야 한다.
- **Rationale:** 편집 환경 차이로 인한 레이아웃 변동을 줄인다.
- **Verification:** Delivery Manifest의 editable/fixed 역할을 확인한다.
- **Exceptions:** 사용자 환경에서 단일 네이티브 형식만 요구하면 생략할 수 있다.

### FILE-010 - 변환 후 재검수
- **Priority:** Critical
- **Statement:** 형식 변환 후 내용, 글꼴, 수식, 링크, 이미지, 페이지와 기능 손실을 다시 검사해야 한다.
- **Rationale:** 변환 성공 메시지는 의미와 레이아웃 보존을 보장하지 않는다.
- **Verification:** 원본·변환본 구조와 렌더를 비교한다.
- **Exceptions:** 동일 형식의 무손실 복사에는 해시 확인으로 대체할 수 있다.

## 14.C 파일명·경로·구조 (FILE-011 ~ FILE-015)

### FILE-011 - 식별 가능한 파일명
- **Priority:** Critical
- **Statement:** 파일명은 프로젝트 또는 문서 ID, 제목, 필요한 버전·상태를 일관된 순서로 식별 가능하게 포함해야 한다.
- **Rationale:** 파일명은 수신자가 기준본을 선택하는 첫 단서다.
- **Verification:** Naming Convention과 실제 파일명을 대조한다.
- **Exceptions:** 외부 시스템이 강제한 이름은 매니페스트에서 역할을 설명한다.

### FILE-012 - 모호한 최종명 금지
- **Priority:** High
- **Statement:** final, new, latest, copy 같은 상대적 표현만으로 파일을 구분하지 않는다.
- **Rationale:** 시간이 지나면 어느 파일이 최신인지 알 수 없다.
- **Verification:** 파일명에 안정적인 식별자와 버전 또는 날짜가 있는지 확인한다.
- **Exceptions:** 임시 작업 사본은 최종 전달 범위 밖에서 사용할 수 있다.

### FILE-013 - 경로 안전성
- **Priority:** Critical
- **Statement:** 금지 문자, 예약어, 끝 공백, 제어 문자와 대상 환경 한계를 넘는 경로 길이를 피해야 한다.
- **Rationale:** 운영체제와 압축 도구 차이로 파일 생성·추출이 실패할 수 있다.
- **Verification:** 대상 환경의 경로 규칙과 패키지 경로를 검사한다.
- **Exceptions:** 원본 이름 보존이 법적 요구이면 안전한 컨테이너와 매핑표를 사용한다.

### FILE-014 - 상대 경로 유지
- **Priority:** High
- **Statement:** 패키지 내부 참조는 이동 후에도 동작하도록 가능한 범위에서 상대 경로를 사용해야 한다.
- **Rationale:** 제작자의 절대 경로는 수신 환경에 존재하지 않는다.
- **Verification:** 다른 루트 위치에 복사해 링크와 의존성을 확인한다.
- **Exceptions:** 승인된 중앙 저장소의 고정 URL은 절대 참조로 유지할 수 있다.

### FILE-015 - 중복 경로 금지
- **Priority:** High
- **Statement:** 동일 역할의 파일을 여러 폴더에 중복 배치하지 않고 하나의 기준 위치를 사용해야 한다.
- **Rationale:** 중복은 수정 누락과 기준본 혼선을 만든다.
- **Verification:** 파일명·해시·역할 기준으로 중복을 검사한다.
- **Exceptions:** 명시된 백업은 최종 사용 위치와 분리해 표시한다.

## 14.D 생성·보존·무결성 (FILE-016 ~ FILE-020)

### FILE-016 - 기존 파일 보존
- **Priority:** Critical
- **Statement:** 사용자 승인 없이 기존 파일을 덮어쓰거나 삭제하지 않는다.
- **Rationale:** 원본 손실은 복구 불가능한 피해를 만들 수 있다.
- **Verification:** 생성 전후 경로와 원본 해시를 비교한다.
- **Exceptions:** 사용자가 정확한 동일 파일 수정을 요청한 경우 변경 전 상태를 확인한다.

### FILE-017 - 출력 경로 제한
- **Priority:** Critical
- **Statement:** 산출물과 중간 파일은 승인된 작업 폴더 또는 명시된 대상 경로 안에 생성해야 한다.
- **Rationale:** 범위 밖 파일 생성은 정리·보안·추적 문제를 만든다.
- **Verification:** 생성 파일 목록과 허용 루트를 비교한다.
- **Exceptions:** 시스템 임시 폴더는 중간 산출물에 사용하고 최종 패키지에서 제외한다.

### FILE-018 - 생성 존재성 검사
- **Priority:** Critical
- **Statement:** 최종 파일이 존재하고 0바이트가 아니며 예상 개수와 크기 범위에 있는지 확인해야 한다.
- **Rationale:** 명령 성공만으로 실제 파일 생성은 보장되지 않는다.
- **Verification:** 파일 목록, 크기와 예상 산출물을 대조한다.
- **Exceptions:** 의도된 빈 데이터 파일은 스키마와 빈 상태를 명시한다.

### FILE-019 - 열림과 구조 검증
- **Priority:** Critical
- **Statement:** 각 최종 파일을 신뢰 가능한 응용 프로그램 또는 파서로 다시 열어 핵심 구조를 확인해야 한다.
- **Rationale:** 손상된 파일도 경로와 크기는 정상일 수 있다.
- **Verification:** 재열기 결과와 형식별 구조 감사를 확인한다.
- **Exceptions:** 실행 환경이 없으면 미검증 제한을 공개하고 전달 승인을 받아야 한다.

### FILE-020 - 무결성 검증값
- **Priority:** High
- **Statement:** 중요·대용량·복합 패키지는 SHA-256 등 검증값과 파일 크기를 제공해야 한다.
- **Rationale:** 전송 중 손상이나 잘못된 파일 교체를 탐지하게 한다.
- **Verification:** 전달 전후 해시와 크기를 비교한다.
- **Exceptions:** 단순 인앱 첨부는 플랫폼 무결성 확인과 수신 열림 검사로 대체할 수 있다.

## 14.E 패키지와 의존성 (FILE-021 ~ FILE-025)

### FILE-021 - 패키지 매니페스트
- **Priority:** Critical
- **Statement:** 둘 이상의 역할 파일을 전달할 때 파일명, 역할, 필수 여부와 기준본을 설명하는 매니페스트를 포함해야 한다.
- **Rationale:** 수신자는 파일 목록만으로 사용 순서를 알기 어렵다.
- **Verification:** 매니페스트와 실제 패키지 파일을 대조한다.
- **Exceptions:** 동일 형식의 단순 연속 이미지 등 자명한 묶음은 규칙을 축약할 수 있다.

### FILE-022 - 의존성 공개
- **Priority:** Critical
- **Statement:** 파일 사용에 필요한 글꼴, 데이터, 라이브러리, 템플릿, 플러그인, 링크와 실행 환경을 명시해야 한다.
- **Rationale:** 숨은 의존성은 수신 환경에서 실패를 만든다.
- **Verification:** 깨끗한 대상 환경에서 열기·실행 결과를 확인한다.
- **Exceptions:** 고정본은 재생성 의존성을 별도 기술할 수 있다.

### FILE-023 - 필수 의존 파일 포함
- **Priority:** Critical
- **Statement:** 재현·열기·실행에 필수인 파일은 권리와 보안이 허용하는 범위에서 패키지에 포함해야 한다.
- **Rationale:** 참조만 있고 파일이 없으면 패키지가 독립적으로 동작하지 않는다.
- **Verification:** 의존성 목록과 포함 파일·접근 경로를 비교한다.
- **Exceptions:** 재배포 불가 자산은 공식 획득 위치와 버전 요구를 제공한다.

### FILE-024 - 압축 구조 단순화
- **Priority:** High
- **Statement:** 압축 패키지는 하나의 최상위 폴더 아래에 목적별 구조를 두고 불필요한 중첩을 피해야 한다.
- **Rationale:** 산개된 추출 파일과 깊은 경로는 사용과 정리를 어렵게 한다.
- **Verification:** 새 위치에 압축을 풀어 최상위 구조와 경로를 확인한다.
- **Exceptions:** 대상 배포 시스템이 지정한 구조를 우선한다.

### FILE-025 - 압축 해제 검증
- **Priority:** Critical
- **Statement:** 최종 압축 파일을 새 임시 위치에 실제로 풀어 파일 수, 구조, 무결성과 핵심 열림을 확인해야 한다.
- **Rationale:** 압축 생성 성공과 정상 복원은 다를 수 있다.
- **Verification:** 원본 패키지와 해제본의 파일 목록·해시를 비교한다.
- **Exceptions:** 플랫폼이 자동 패키징하고 검증할 수 없는 경우 제한을 기록한다.

## 14.F 보안·개인정보·권한 (FILE-026 ~ FILE-030)

### FILE-026 - 비밀정보 제외
- **Priority:** Critical
- **Statement:** 비밀번호, API 키, 토큰, 인증서 개인키와 기타 비밀값을 승인되지 않은 전달 파일에 포함하지 않는다.
- **Rationale:** 비밀정보 노출은 계정과 시스템 침해로 이어질 수 있다.
- **Verification:** 비밀정보 패턴 검사와 수동 검토를 수행한다.
- **Exceptions:** 승인된 비밀 전달 시스템과 암호화 절차를 사용하는 경우에만 별도 처리한다.

### FILE-027 - 개인정보 최소화
- **Priority:** Critical
- **Statement:** 개인정보와 민감정보는 목적에 필요한 최소 범위만 포함하고 불필요한 값은 제거·마스킹해야 한다.
- **Rationale:** 과도한 정보 전달은 침해 영향과 규정 위험을 높인다.
- **Verification:** 데이터 필드와 전달 목적·보유 근거를 대조한다.
- **Exceptions:** 법적 보존·제출 요구는 승인된 보호 절차를 따른다.

### FILE-028 - 숨은 메타데이터 검사
- **Priority:** Critical
- **Statement:** 댓글, 추적 변경, 작성자 정보, 개인 경로, 숨은 시트·레이어와 문서 속성을 전달 전 검사해야 한다.
- **Rationale:** 화면에 보이지 않는 정보도 파일 안에 남아 노출될 수 있다.
- **Verification:** 형식별 메타데이터와 숨은 콘텐츠 감사를 실행한다.
- **Exceptions:** 검토본에 필요한 댓글·추적 변경은 존재와 공개 범위를 명시한다.

### FILE-029 - 최소 권한 공유
- **Priority:** Critical
- **Statement:** 공유 링크와 저장소 권한은 의도한 수신자에게 필요한 읽기·편집 범위와 기간만 부여해야 한다.
- **Rationale:** 과도한 권한은 무단 접근과 변경 위험을 높인다.
- **Verification:** 실제 공유 대상, 권한, 만료와 상속 설정을 확인한다.
- **Exceptions:** 명시적으로 승인된 공개 배포는 공개 범위와 내용을 다시 확인한다.

### FILE-030 - 보호정보 분리 전달
- **Priority:** High
- **Statement:** 암호화 파일의 비밀번호나 복구 정보는 가능한 경우 파일과 다른 승인 채널로 전달해야 한다.
- **Rationale:** 같은 경로가 노출되면 암호화 효과가 크게 줄어든다.
- **Verification:** 파일과 비밀번호 전달 채널 기록을 확인한다.
- **Exceptions:** 승인된 종단간 암호화 시스템이 통합 보호를 제공하면 그 절차를 따른다.

## 14.G 호환성·접근성·사용성 (FILE-031 ~ FILE-035)

### FILE-031 - 대상 환경 열림 검사
- **Priority:** Critical
- **Statement:** 핵심 파일은 지정된 대상 환경에서 열리고 읽히며 필요한 기능이 동작하는지 확인해야 한다.
- **Rationale:** 제작 도구에서만 정상인 파일은 전달 목적을 충족하지 못한다.
- **Verification:** Compatibility Matrix의 대상별 결과를 확인한다.
- **Exceptions:** 환경 접근이 없으면 지원 환경과 미검증 범위를 명시한다.

### FILE-032 - 글꼴·자산 처리
- **Priority:** High
- **Statement:** 수신 환경에 없을 수 있는 글꼴·코덱·플러그인은 포함, 임베드, 대체 또는 고정본 제공으로 처리해야 한다.
- **Rationale:** 누락 자산은 레이아웃, 문자와 미디어를 깨뜨린다.
- **Verification:** 깨끗한 환경의 렌더·재생 결과를 확인한다.
- **Exceptions:** 라이선스상 포함할 수 없으면 공식 설치 위치와 대체 결과를 제공한다.

### FILE-033 - 기계 처리 검증
- **Priority:** Critical
- **Statement:** CSV, JSON, XML, 코드와 기타 기계 처리 파일은 인코딩, 스키마, 구분자, 줄바꿈과 파싱 가능성을 검증해야 한다.
- **Rationale:** 시각적으로 보이는 텍스트와 실제 파싱 성공은 다르다.
- **Verification:** 대상 파서 또는 스키마 검증을 실행한다.
- **Exceptions:** 샘플 파일은 샘플임을 표시하고 적용 범위를 제한한다.

### FILE-034 - 사용 안내 제공
- **Priority:** High
- **Statement:** 추출, 설치, 열기, 실행, 매크로, 데이터 연결 등 비자명한 단계는 짧은 사용 안내로 제공해야 한다.
- **Rationale:** 파일이 정상이어도 사용 방법을 모르면 실패로 인식된다.
- **Verification:** 수신자 관점에서 안내만으로 첫 실행을 재현한다.
- **Exceptions:** 표준 형식의 단일 열기 파일은 생략할 수 있다.

### FILE-035 - 접근성 정보 유지
- **Priority:** High
- **Statement:** 변환·압축·패키징 과정에서 문서 태그, 대체 텍스트, 읽기 순서와 의미 있는 파일명이 불필요하게 손실되지 않아야 한다.
- **Rationale:** 전달 과정의 평면화가 접근성을 제거할 수 있다.
- **Verification:** 원본과 전달본의 접근성 구조를 비교한다.
- **Exceptions:** 대상 형식이 지원하지 않으면 대체 파일이나 제한을 제공한다.

## 14.H 다운로드·전송·수신 (FILE-036 ~ FILE-040)

### FILE-036 - 실제 접근 가능성
- **Priority:** Critical
- **Statement:** 전달 위치와 링크는 수신자의 실제 계정·권한·지역에서 접근 가능해야 한다.
- **Rationale:** 제작자에게 열리는 링크가 수신자에게도 열린다고 보장할 수 없다.
- **Verification:** 수신자 권한 또는 동등한 비소유자 환경으로 접근을 확인한다.
- **Exceptions:** 권한 부여가 수신자 행동에 의존하면 필요한 요청 절차를 명시한다.

### FILE-037 - 링크 대상 일치
- **Priority:** Critical
- **Statement:** 전달 링크가 의도한 최신 파일, 올바른 이름과 기준본으로 연결되는지 확인해야 한다.
- **Rationale:** 오래된 링크와 유사 파일은 잘못된 산출물 사용을 만든다.
- **Verification:** 링크를 다시 열어 대상 식별자·해시와 비교한다.
- **Exceptions:** 버전 목록 링크는 사용해야 할 정확한 항목을 지정한다.

### FILE-038 - 링크 만료와 지속성
- **Priority:** High
- **Statement:** 링크 만료, 다운로드 횟수, 세션 요구와 보존 기간이 사용 일정에 충분한지 확인해야 한다.
- **Rationale:** 수신자가 필요한 시점에 파일을 얻지 못할 수 있다.
- **Verification:** 링크 정책과 사용·검토 일정을 비교한다.
- **Exceptions:** 일회성 보안 링크는 재발급 절차를 함께 제공한다.

### FILE-039 - 수신 확인
- **Priority:** High
- **Statement:** 중요·민감·마감 연계 전달은 수신 또는 다운로드와 정상 열림을 확인해야 한다.
- **Rationale:** 전송 성공 표시가 실제 수신과 사용 가능성을 보장하지 않는다.
- **Verification:** 수신 확인, 시스템 영수증 또는 후속 열림 결과를 확인한다.
- **Exceptions:** 공개 다운로드는 가용성 모니터링으로 대체할 수 있다.

### FILE-040 - 전달 메시지 완결성
- **Priority:** Critical
- **Statement:** 전달 메시지에는 목적, 파일 목록, 기준본, 사용 안내, QA 상태, 제한과 다음 행동을 포함해야 한다.
- **Rationale:** 파일만 보내면 수신자가 역할과 상태를 추측해야 한다.
- **Verification:** Delivery Message 체크리스트를 확인한다.
- **Exceptions:** 단일 자명한 파일은 목적, 상태와 파일 식별자로 축약할 수 있다.

## 14.I 실패·복구·재전달 (FILE-041 ~ FILE-045)

### FILE-041 - 전달 실패 투명성
- **Priority:** Critical
- **Statement:** 업로드, 첨부, 권한, 다운로드, 압축 해제와 열기 실패를 성공으로 보고하지 않는다.
- **Rationale:** 숨은 실패는 마감과 후속 작업을 중단시킨다.
- **Verification:** 전송 로그와 사용자에게 보고한 상태를 비교한다.
- **Exceptions:** 없음.

### FILE-042 - 실패 정보 기록
- **Priority:** High
- **Statement:** 전달 실패에는 대상, 시각, 단계, 오류, 영향, 시도한 조치와 필요한 다음 행동을 기록해야 한다.
- **Rationale:** 구체적 정보가 있어야 동일 실패를 반복하지 않고 복구할 수 있다.
- **Verification:** Delivery Incident 기록의 필수 필드를 확인한다.
- **Exceptions:** 일시적 자동 재시도로 즉시 복구된 오류는 묶음 기록할 수 있다.

### FILE-043 - 대체 경로 통제
- **Priority:** Critical
- **Statement:** 기본 채널 실패 시 보안·권한·크기 요구를 충족하는 승인된 대체 경로만 사용해야 한다.
- **Rationale:** 편의상 비승인 채널을 쓰면 보호 요구가 무력화된다.
- **Verification:** 대체 채널 승인과 접근 설정을 확인한다.
- **Exceptions:** 긴급 안전 대응은 상위 규칙에 따라 최소 범위로 보고·승인한다.

### FILE-044 - 재전달 식별
- **Priority:** Critical
- **Statement:** 수정본이나 재전달 파일은 이전 전달과 구분되는 식별자, 변경 이유와 대체 관계를 명시해야 한다.
- **Rationale:** 수신자가 폐기할 파일과 사용할 파일을 알아야 한다.
- **Verification:** 재전달 메시지와 이전·현재 파일 식별자를 비교한다.
- **Exceptions:** 동일 바이트의 링크 재발급은 해시 동일성과 새 만료만 표시할 수 있다.

### FILE-045 - 재전달 재검증
- **Priority:** Critical
- **Statement:** 재전달 전 최종 파일, 링크, 권한, 무결성과 전달 메시지를 다시 검증해야 한다.
- **Rationale:** 실패 복구 과정에서 다른 파일이나 잘못된 권한이 적용될 수 있다.
- **Verification:** Re-delivery Checklist와 최종 결과를 확인한다.
- **Exceptions:** 없음.

## 14.J 최종 게이트와 기록 (FILE-046 ~ FILE-050)

### FILE-046 - QA 통과본만 전달
- **Priority:** Critical
- **Statement:** 사용자에게 완료본으로 전달하는 파일은 COR-005 품질 게이트를 통과한 정확한 대상이어야 한다.
- **Rationale:** 검수 전 파일이나 검수 후 변경본은 완료 상태로 신뢰할 수 없다.
- **Verification:** QA 대상 해시와 전달 파일 해시를 비교한다.
- **Exceptions:** 명시적 중간 검토본은 REVIEW 또는 DRAFT로 표시한다.

### FILE-047 - 기준본 단일 표시
- **Priority:** Critical
- **Statement:** 여러 변형을 전달할 때 현재 사용 기준본과 각 파일의 역할을 하나로 명확히 표시해야 한다.
- **Rationale:** 사용자가 편집본·고정본·참고본 중 잘못된 파일을 선택할 수 있다.
- **Verification:** Manifest와 전달 메시지의 canonical 표시를 확인한다.
- **Exceptions:** 동등한 채널별 변형은 동일 내용과 용도를 명시한다.

### FILE-048 - 전달 후 변경 금지
- **Priority:** Critical
- **Statement:** 전달한 파일이나 링크 대상을 알림 없이 다른 내용으로 교체하지 않는다.
- **Rationale:** 동일 식별자가 다른 바이트를 가리키면 검수와 기록이 무효화된다.
- **Verification:** 전달 시점과 현재 대상의 해시·버전을 비교한다.
- **Exceptions:** 관리형 최신 링크는 변경 알림과 버전 이력을 제공해야 한다.

### FILE-049 - 전달 기록 보존
- **Priority:** High
- **Statement:** 필요한 수준으로 파일 식별자·해시, 전달 시각, 채널, 수신자, 권한, 만료와 결과를 기록해야 한다.
- **Rationale:** 기록은 누가 무엇을 받았는지 재현하고 사고를 조사하게 한다.
- **Verification:** Delivery Log의 필수 필드를 확인한다.
- **Exceptions:** 저위험 단일 로컬 전달은 위치, 시각과 파일 식별자로 축약할 수 있다.

### FILE-050 - 미완료 전달 금지
- **Priority:** Critical
- **Statement:** 필수 파일 누락, 무결성 실패, 접근 불가, 열린 Critical 결함 또는 미해결 민감정보 위험이 있으면 완료 전달로 표시하지 않는다.
- **Rationale:** 전달 성공과 산출물 완료를 혼동해서는 안 된다.
- **Verification:** 열린 Delivery Blocker와 최종 전달 상태를 비교한다.
- **Exceptions:** 사용자가 제한을 수용한 부분 전달은 PARTIAL로 표시하고 누락·위험·다음 조치를 명시한다.

# 15. 표준 파일 전달 수명주기

모든 JCOS 파일 전달은 아래 순서를 기본으로 한다.

1. **Brief** - 수신자, 목적, 대상 환경, 형식, 필수 파일과 채널 제약을 확인한다.
2. **Generate** - 기존 파일을 보존하며 승인된 경로에 요구 형식으로 생성한다.
3. **Validate** - 확장자·구조·열림·내용·렌더링·기계 처리를 형식에 맞게 검증한다.
4. **Package** - 파일명, 폴더, 매니페스트, 의존성, 사용 안내와 검증값을 정리한다.
5. **Protect** - 비밀·개인정보·숨은 메타데이터와 공유 권한을 검사한다.
6. **Transfer** - 올바른 파일과 완결된 메시지를 승인된 접근 경로로 전달한다.
7. **Confirm** - 링크·권한·다운로드·수신·열림과 필요 시 무결성을 확인한다.
8. **Record** - 전달 대상, 결과, 제한, 만료, 실패와 재전달 이력을 보존한다.

완료 전 QA는 COR-005, 버전·승인 상태는 COR-007, 채널별 공개 발행은 후속 Publishing System을 따른다.

# 16. 준수 체크리스트

## 16.1 전달 준비

- [ ] 수신자, 목적, 편집 필요와 대상 환경을 확인했다.
- [ ] 필수·선택 파일, 원본 자산과 설명 자료를 정의했다.
- [ ] 형식, 크기, 권한, 만료와 보안 제약을 확인했다.
- [ ] 파일명이 안정적인 식별자와 필요한 버전·상태를 포함한다.
- [ ] 기존 사용자 파일을 보존하고 승인된 출력 경로를 사용했다.

## 16.2 파일과 패키지

- [ ] 확장자와 내부 형식이 일치하고 모든 파일이 정상적으로 열린다.
- [ ] 편집본·고정본의 역할과 기준본이 명확하다.
- [ ] 변환 후 내용·레이아웃·기능 손실을 재검수했다.
- [ ] 매니페스트가 실제 파일, 역할과 필수 여부와 일치한다.
- [ ] 의존성, 상대 경로, 압축 해제와 무결성을 확인했다.

## 16.3 보안과 호환성

- [ ] 비밀값, 불필요한 개인정보와 내부 자료가 없다.
- [ ] 댓글, 추적 변경, 숨은 데이터와 메타데이터를 검사했다.
- [ ] 공유 대상, 권한과 만료가 최소 필요 범위다.
- [ ] 대상 환경에서 열림·기능·글꼴·자산을 확인했다.
- [ ] 사용 안내와 적용 가능한 접근성 정보를 유지했다.

## 16.4 전달과 확인

- [ ] COR-005를 통과한 정확한 파일 해시를 전달한다.
- [ ] 링크가 최신 기준본으로 연결되고 실제 접근 가능하다.
- [ ] 전달 메시지에 목적, 파일, 기준본, QA, 제한과 다음 행동이 있다.
- [ ] 중요한 전달의 다운로드·수신·열림을 확인했다.
- [ ] 실패·재전달·잔여 제한과 전달 결과를 기록했다.
