# 작업별 적용 수준 검토안

| 항목 | 값 |
|---|---|
| Document ID | FND-006 |
| Version | 0.1.0-rc.1 |
| Status | REVIEW |
| Owner | JCOS Maintainers |

이 문서는 절차 경량화의 검토 후보입니다. 기존 LOCKED 규칙에 예외를 새로 부여하지 않으며, 프로젝트가 채택하기 전에 영향을 받는 Core·Content·Automation 기준본의 호환성·버전·QA·승인을 함께 검토해야 합니다.

## 선택 기준

| 수준 | 적용 조건 | 제안하는 최소 기록 | 추가 요구 |
|---|---|---|---|
| SIMPLE | 로컬 내부 초안, 가역적 문장 수정, 새로운 사실 없음, 외부 부작용 없음 | 요청·대상·원문·수정문·범위·검사 결과를 하나의 기록에 통합 | 기존 기준의 필수 항목은 유지하거나 승인된 새 기준에서 대체 |
| STANDARD | 조사·기사·보고서·다중 형식 제작 | 기준본 연결, 주장·출처·근거, 버전, 품질·전달 기록 | 레이아웃 전수 검수, 파생 형식 의미 정합 |
| CONTROLLED | 게시·예약 실행·삭제·외부 전송·권한 변경 또는 중요 위험 | STANDARD 기록과 정확한 대상·승인·실행·외부 상태 기록 | 멱등성, 복구·중지 경로, 부분·미확인 상태 관리 |

SIMPLE은 글의 길이만으로 선택하지 않습니다. 짧은 문장이라도 중요한 사실을 새로 주장하거나 외부에 게시하면 상위 수준의 검토가 필요합니다. 판단이 불명확하면 작업 영향을 먼저 확인합니다.

모든 수준에서 사실성, 기밀 보호, MASTER 보호와 실패의 정직한 보고를 유지합니다. 기록은 합칠 수 있지만 필요한 근거를 없애지 않습니다. 임의의 비용·시간 임계값은 정의하지 않습니다.

## 채택과 검증 계획

1. CNT-002의 Research Handoff·Claim Trace·필수 입력 요구와 AUT-003의 Prompt 계약에 대한 영향표를 작성합니다.
2. SIMPLE 대체 기록이 기존 요구와 동등한지 검증합니다. 필수 조건을 완화한다면 영향 문서의 Major 변경을 검토합니다.
3. 내부 문장 수정, 새 수치 추가, 외부 게시, 대상 미확인, 부분 성공 사례를 회귀 검증합니다.
4. 정확한 후보 버전과 QA 결과에 대한 승인을 기록한 뒤 프로젝트가 명시적으로 채택합니다. 자동 승격하지 않습니다.

## 학습 예제와의 관계

[로컬 예제](../examples/README.md)는 선택 기준과 입력 검증을 학습하기 위한 것으로, 전체 JCOS 준수나 SIMPLE 프로필의 운영 승인을 증명하지 않습니다.
