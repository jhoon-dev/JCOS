# 공개판의 프로젝트 상속 안내

이 문서는 [아키텍처](../00_FOUNDATION/ARCHITECTURE.md)의 계층과 현재 로컬 편집 도구의 파일을 연결하는 사용 안내입니다. 새 규범 기준본이나 승인된 프로젝트 모듈을 정의하지 않습니다.

## 계층과 실제 파일

| 계층 | 공개판에서 연결되는 파일 | 역할 |
|---|---|---|
| CORE | 등록부에 기록된 `01_CORE` 문서 | 공통 규칙의 기준본 |
| PROJECT MODULE | 로컬 `project.json` | 프로젝트 정체성·범위·기준본 참조를 담는 최소 입력 계약 |
| MASTER | 로컬 프로젝트의 별도 승인 자산 | 현재 로컬 편집 예제에서는 `master: null` |
| EXECUTION | 로컬 `request.json` | 이번 작업의 목적·독자·언어·원문·결과 계약 |
| OUTPUT | 실제 실행 후 생성하고 검수할 산출물 | 현재 도구는 AI 산출물을 생성하지 않음 |

`project.json`은 전체 프로젝트 모듈의 승인 절차와 모든 필드를 구현하지 않습니다. 아키텍처의 YAML `inherits` 예시는 개념 설명이며 초기화 도구가 읽는 설정 형식은 JSON입니다. 실제 필드는 [공통 템플릿](local-editing/project.json)과 [가상 요청](../examples/request.json)을 확인합니다.

## 참조와 스냅샷

1. `project.json`의 `baseline_refs`는 `COR-001` 같은 문서 ID를 나열합니다. 공통 원문을 프로젝트별로 복사·수정하지 않습니다.
2. `request.json`의 `project_ref`는 요청 폴더 안의 프로젝트 JSON을 가리킵니다. 검사기는 요청 폴더 밖으로 나가는 참조를 거부합니다.
3. 검사기는 도구가 위치한 JCOS-public 체크아웃의 [등록부](../00_FOUNDATION/document_registry.json)에서 각 ID의 활성 기준본과 상태·해시를 확인합니다. 작업 디렉터리나 형제 `JCOS` 저장소에서 기준본을 자동으로 찾지 않습니다.
4. `prepare_work.py`는 입력을 검증한 뒤 `package.json`에 프로젝트·요청 스냅샷, 입력과 등록부의 해시, 선택한 기준본의 ID·버전·상태·경로·해시를 기록합니다.

`baseline_refs` 자체는 버전 잠금 파일이 아닙니다. 체크아웃의 활성 등록부가 바뀌면 같은 ID가 다른 버전으로 해석될 수 있습니다. 재현이 필요한 작업은 사용한 체크아웃의 커밋과 생성한 패키지를 함께 보관합니다. 패키지는 당시 선택의 기록이며 후속 실행에서 버전을 자동 고정하는 기능은 없습니다.

## 공통 파일과 로컬 파일의 경계

| 위치 | 관리할 내용 |
|---|---|
| `templates/local-editing/` | 사용자 값이 비어 있는 재사용 템플릿 |
| `examples/` | 공개 가능한 가상 학습 입력 |
| `local-work/<project>/` 또는 별도 프로젝트 저장소 | 사용자 설정과 실행 요청 |
| 매번 새로 지정한 패키지 폴더 | `package.json`, `prompt.json`, `result.json` |

`local-work/`는 공개 저장소의 Git 제외 대상입니다. 별도 저장소를 쓰면 그 저장소에서 공개 범위와 제외 정책을 관리합니다. 실제 프로젝트 설정과 실행 기록을 공통 템플릿이나 공개 예제로 옮기지 않습니다. 형제 `JCOS` 저장소의 프로젝트·QA·이력도 자동으로 상속하거나 동기화하지 않습니다.

## 시작과 기준본 업데이트

먼저 [초기화 안내](README.md)에 따라 새 로컬 계약을 만들고 [dry-run 안내](../examples/DRY_RUN.md)에 따라 새 폴더에 패키지를 준비합니다. 기존 대상 폴더는 덮어쓰지 않습니다.

공통 기준본을 업데이트할 때는 기존 프로젝트·요청·패키지를 보존하고, 후보 체크아웃의 문서 검사를 실행합니다. 기존 패키지의 `baselines`와 후보 등록부에서 실제 참조하는 기준본의 버전·상태·해시를 비교한 뒤 프로젝트에 미치는 영향을 검토합니다. 적용하기로 결정한 체크아웃에서 요청을 다시 검사하고 새 폴더에 패키지를 생성해 적용 기록을 남깁니다. 정적 검사 통과가 변경 승인이나 프로젝트 QA를 대신하지 않습니다.

현재 `prompt.json`은 제한된 로컬 편집 정책과 작업 데이터를 제공합니다. 기준본 원문 전체 또는 Core Runtime을 자동 삽입하지 않습니다. `result.json`의 `DRY_RUN`과 `content_quality: NOT_RUN`은 준비 상태이며, OUTPUT이나 MASTER 승인 상태가 아닙니다. 게시·예약·외부 변경과 승인된 Project Runtime은 별도 계약·검토가 필요한 범위입니다.
