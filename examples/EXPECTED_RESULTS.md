# 예상 결과와 경계 사례

## 정상 결과

검사 명령은 `PASS: local editing example input`을 반환합니다. 편집자가 만들 수 있는 결과 예시는 다음과 같습니다. 실제 AI 실행을 수행한 결과는 아닙니다.

```json
{
  "status": "COMPLETE",
  "revised_text": "검토 후 의견을 보내 주세요.",
  "checks": ["요청 행동 유지", "새 사실 추가 없음", "MASTER 변경 없음", "외부 부작용 없음"],
  "limitations": ["가상 로컬 편집 예제", "전체 JCOS 운영 QA와 승인 범위 밖"]
}
```

## 실패·부분 성공·미확인

| 사례 | 입력 검사 또는 실행 결과 | 후속 행동 |
|---|---|---|
| 목적·독자·원문 누락 | 입력 검사 FAIL | 누락 항목을 채운 뒤 다시 검사 |
| SIMPLE에서 새 사실 추가 요청 | 입력 검사 FAIL | 출처·근거를 갖춘 STANDARD 계약 검토 |
| SIMPLE에서 게시·외부 전송 요청 | 입력 검사 FAIL | 대상·권한·승인·복구가 있는 CONTROLLED 계약 검토 |
| 원문 참조 파일 또는 기준본 해시 불일치 | 입력 검사 FAIL | 정확한 프로젝트·기준본 확인 |
| 여러 요청 중 일부만 완료 | 실행 결과 PARTIAL | 성공·실패 항목을 각각 기록; 전체 완료 선언 금지 |
| 외부 변경 응답을 받지 못함 | 실행 결과 UNKNOWN | 원격 상태 확인 전 같은 변경 반복 금지 |

PARTIAL·UNKNOWN은 운영 결과 설명 예시이며 로컬 입력 검사에서 발생시키는 상태가 아닙니다. 입력 검사 PASS만으로 편집 결과의 의미 보존을 확인했다고 주장하지 않습니다.
